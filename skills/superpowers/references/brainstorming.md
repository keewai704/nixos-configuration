# Brainstorming

Use this when a material requirement or design choice is unresolved, not to
reopen a settled decision.

Inspect the affected flow, callers, and constraints. Identify the intended
behavior, scope, important failure cases, and acceptance criteria. Reuse what
the user has already supplied. Make routine choices from existing conventions;
ask a focused question only when the answer changes the solution.

Compare alternatives when a real trade-off exists, then recommend one. Explain
the changed flow, interfaces, data, and verification at the level needed to make
the decision. Include security and compatibility where affected.

Deliver a concrete design. For an implementation request, continue once material
uncertainty is resolved; honor an explicitly requested approval checkpoint.
Keep the design in the conversation unless a durable artifact is requested or
required. Use the repository's permitted location rather than creating a docs
tree, browser companion, or ceremonial sign-off.
