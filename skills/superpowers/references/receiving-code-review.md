# Receiving Code Review

Evaluate findings against the requirement, caller, and failure scenario rather
than accepting or rejecting them by authority.

Read the complete finding and relevant implementation. Reproduce the issue or
reason from concrete evidence. Ask for clarification only when ambiguity changes
the repair; continue independent clear work. Reject incorrect findings with
evidence, and separate optional style preferences from requested scope.

Fix security, correctness, and blocking requirement gaps first. Keep repairs
focused and run affected checks. Feedback does not expand authorization or
justify unrelated refactoring.

Report what was fixed, rejected with reasons, or left blocked. Obtain follow-up
on changed or unresolved areas when required; agreement or a promise is not a
verified repair.
