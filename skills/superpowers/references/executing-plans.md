# Executing Plans

The parent implements the plan in the current session. Use separate implementer
contexts only when task independence or specialization makes them worthwhile.

Check the plan against the current checkout and request. Resolve genuine gaps
before the affected step; continue independent authorized work while blocked.
Update stale paths and assumptions from evidence.

Execute cohesive tasks in dependency order. Track decisions, completed work,
and check results in session notes so continuation does not redo finished tasks.
Verify changed behavior with the appropriate tests, loaders, builds, or runtime
checks. Investigate failures rather than stacking speculative repairs.

Give progress updates at meaningful milestones. Do not stop after an arbitrary
batch for renewed permission. After integration, obtain the independent review
required by the active policy, resolve actual findings, and complete required
commit and activation gates. Report unfinished work and concrete blockers rather
than returning a first draft as complete.
