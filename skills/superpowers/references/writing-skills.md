# Writing Skills

Use this when creating or materially revising reusable workflow guidance.

Identify the recurring task or observed failure. Give the skill one focused
purpose and a short description with precise matching conditions. Avoid triggers
that sweep in an entire subject when the skill handles only one operation.

Use the target loader's documented Agent Skills format. For Nix-managed personal skills, use `add-nix-skill` and edit repository sources.
Make a multi-workflow root a small router to supporting references or scripts.
Read only the branch needed for the task, and keep references directly reachable
rather than creating a chain of mandatory skill reads. Keep authority and safety
boundaries in the root or the reference loaded before the affected action.

Describe outcomes, inputs, decision boundaries, and completion evidence. Leave
routine implementation choices to the agent. State conditional behavior where it
applies; avoid duplicate repository policy, rigid itineraries, universal approval
waits, and unavailable harness tools. Retain useful license and source provenance.

Use the target loader for frontmatter, discovery, and duplicate-name validation;
check linked resources separately. Check matching, non-matching, ambiguous, and
blocked requests. A bounded isolated model evaluation can test material behavior
when available and authorized; otherwise report a manual scenario review, not
behavioral proof. Use baseline comparisons for observed regressions, not every
wording change. Do not add automatic verifier agents or generic second-pass rituals.

Repair observed gaps and rerun affected checks. Never delete work because tests
came later. Complete required review and deployment, verify deployed content,
and avoid restarting the application that owns the active task.
