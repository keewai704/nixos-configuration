# Native Pi delegation checks

Use disposable HOME/agent state, synthetic local providers, and disposable Git
repositories with explicit committed writer inputs. Never use real credentials,
sessions, or paid APIs. For resource/config-only changes, exercise affected loading
and bridge paths; do not rerun unchanged controller/browser-navigation suites.

## Loading and capability boundaries

Run package-local shared runtime and adapter tests using the pinned Pi SDK. Load
the built CLI artifact and Web adapter with configured filters. Check one
registration of `Agent`, `get_subagent_result`, `steer_subagent`, and
`manage_subagents`, six exact roles, and actual child tool/model/provider bindings.

Preserve MCP/search/LSP resources without making those ambient packages production
build dependencies. Code Mode and its retired conversion fixture are not part of
the configured runtime. Check managed role links are discoverable and read-only.
Keep native settings enabled; old plugin registrations and loaded skills/prompts
must be absent.

Exercise root/child/grandchild tool calls, immediate-parent results, read-only
capability ceilings, third-level rejection, and subtree cancellation/shutdown.
Retained pre-change children must keep their captured tool scope.

## Lifecycle, delivery, and model context

Verify concurrency across batches/resumes, dependency failure and explicit
integrated-change release, messages, input requests, follow-up, verified close,
durable delivery, parent process ownership, and teardown before resume. Capture
actual parent model requests and run counts, not only notification callback mocks.

Explicitly tagged progress must stay outside model, summary, and inherited context.
Unread reports, failures, and input requests remain actionable. Surfaced reports,
verified close, and superseded attempts must not cause acknowledgement-only turns.

Cover foreground waits, mixed notice batches, cancellation, aborts, restart,
undurable receipts, foreign observers, and preserved user steering. Verify native
provenance and live/history/reconnect agreement without rewriting old entries or
weakening stale-session guards; retain unknown custom-message handling.

Confirm no automatic commits, merges, worktree deletion, or restart replay;
preserve abandoned work. A launch receipt or accepted message is not completion
or consumption.

## Web behavior and deployment

Confirm compact session rows and conversation shortcuts at mobile and desktop
widths. Do not add task counters, task cards, or parent-control forms. Sessions
without child conversations must retain the original toolbar. Exercise original
conversation navigation, reconnect, and retained history at both widths. Verify
task controls through native tools/shared API without another management UI.

After each activation gate, check deployed CLI/Web resource loading, native
lifecycle, service health, and canonical `/pi/` assets and events. Isolated provider
tests do not prove live authentication. Never reload the migration session.
